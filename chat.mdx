## 发消息与资料

桌面聊天里回车发送，Shift + 回车换行。未发出的内容留作草稿。可以粘贴或选择文件、图片，再说明怎么处理。

> 比较这两份方案，列出会影响实验结论的差异。输出表格，每项引用原文位置。

在群里用 `@` 指定成员，接着旧工作时回复原消息。需要执行者查看的资料，一起提供为附件或可访问链接。

*界面动画：从已有消息展开话题，在旁边继续讨论。视频内置中文字幕。*

1. 找到要继续讨论的消息，打开消息菜单，选择「开话题」。
2. 话题名默认取自原消息，可以修改，随后直接发言。
3. 在话题里 `@` 需要参与的人或 Agent。

桌面保留来源聊天，话题在旁边展开；手机点进去后，用左上返回回到来源聊天。

| 问题 | 普通话题的规则 |
|---|---|
| 群里其他人看得见吗 | 来源群能看见，也能点进来读 |
| 哪些人收到后续通知 | 在里面说话或被点名加入的参与者 |
| 新建话题会换一个 Agent 或工作目录吗 | 不会，仍由同一位 Agent 在原运行位置工作 |
| 老话题从列表消失了怎么办 | 在来源聊天的历史话题中查找；有新发言会再出现 |

## 悄悄话

从群成员的资料卡进入悄悄话。内容只有发送者和那一位成员可见，消息上会标明范围。需要团队共同知道的结论和成品，发回群或话题。

## Android 与其他应用互传

长按消息，进入「转发 → 分享到其他应用」，用系统分享把支持的文字、图片或文件交给微信、邮件等应用。

其他应用把资料分享到咕咕时，先选择要发送到的聊天；内容放进输入框后可以补一句要求，按发送才会发出。若微信没有提供外部分享入口，可复制文字，或对文件使用「用其他应用打开」。

## 回复、失败与重试

Agent 工作时展示实际过程，回复逐步出现。按连接、登录或额度提示分别处理。

重试前检查上轮是否已经产生文件或外部操作，再说明从哪里继续。任务中的消息编辑、排队和归档，见[任务工作区](/tasks)。
