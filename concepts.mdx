title: "几个基本概念"
description: "用一次组会准备，分清助理、Agent、任务、项目、群和设备。"
---

假设要准备一次组会：资料在电脑里，先整理文献，再做提纲，最后和同学一起检查。咕咕里的这些东西各管一部分。

| 名称 | 在一次组会中怎么用 |
|---|---|
| 个人助理 | 记住提纲保持一页，安排整理资料并跟进 |
| Agent | 为你读文件、写提纲的执行者，使用 Codex、Claude Code 等引擎 |
| 模型 | 选择执行时使用的模型，以及自己的订阅或咕咕积分 |
| 任务 | 保留「整理组会文献」这次工作的要求、过程和结果 |
| 项目 | 把同一课题的文献、实验、论文稿和任务放在一起 |
| 文件夹与设备 | 指定材料实际在哪，例如笔记本的论文目录 |
| 群 | 人和 Agent 讨论、交接结果；项目有对应的群 |
| 话题 | 从群里一条消息展开具体讨论，例如单独改第三张图 |


## 一次任务可以独立做

临时整理一段记录，直接新建任务，不必先建项目。需要持续生产、反复使用相同资料时，再把相关文件夹和任务归到项目。

项目可以跨文件夹、跨设备。一条任务执行时仍在选定的一台设备上。选择多台设备作为项目范围，不会把同一个任务自动复制到每台机器。

## 一条任务也有一个可点名的 Agent

任务标题用来找工作，Agent 名字用来在聊天中点名。同一条任务的 Agent 可以参与项目群，不需要再建一个同样的执行者。

个人助理在自己的入口接待；它派出的执行者出现在任务里。点开执行者，可以直接和它聊，同时继续向个人助理提其他问题。

## 项目共享关系，文件按位置保存

把另一台机器的文件夹挂进同一个项目，大家就能围绕同一件事协作。文件内容仍保存在各自设备上。

要共同查看成品，发附件或放进群文件夹。要继续工作，打开原任务。要让另一位 Agent 接手，说明目标、已确认的结论和交付位置。
