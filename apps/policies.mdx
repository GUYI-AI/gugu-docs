---
title: "开发者政策与权限"
description: "现有的强制规则、提交时建议说明的内容，以及维护者在 PR 上的审阅。"
---

目前没有单独发布的完整 App 开发者政策，也没有独立的 CONTRIBUTING 文件、审核时限或申诉流程。现有要求来自产品接口的限制、索引仓的 README 和校验脚本，以及维护者在 PR 上的代码审阅。下面区分强制规则和建议说明。

## 当前强制规则

- 市场只收录按固定源码提交打出的包。源码必须公开可审阅，不能只交一个来源不明的压缩包。
- 已发布的版本不能修改、删除或复用版本号。撤回、停止维护和下架通过登记字段处理。
- 页面受沙箱和网络规则约束。需要额外能力时在 manifest 里申请，由使用者在咕咕的确认单上同意，之后可以逐项撤销。
- 提供本机程序、技能或常驻说明的 App 必须申请 `agents:tools`。程序以使用者的本机权限运行，安装确认单显示实际命令。
- `firstRun` 只能标在代码就在官方索引仓里的 App 上。其他 App 不会被静默安装。
- 每一版登记都由维护者在 PR 上审阅后合并。CI 通过不会自动上架。

## 提交时说明什么

为了让使用者能判断、让维护者能审阅，建议在 README 和 PR 说明里写清：

- 主要用途，以及每项权限和网络主机的理由。
- 访问哪些外部服务，保存哪些数据，存在哪里，卸载时清理什么。
- 支持的设备和客户端版本。
- 需要连接账号时，使用者在哪里配置。不要把密钥打进包里。

引用第三方库或复制示例代码时，核对并保留对应的许可证。manifest 的 `license` 只是文本，平台不验证。

启动和联系 Agent 会消耗使用者的额度。说明 App 什么时候会启动或联系 Agent，不要让 Agent 互相无限唤醒。多人数据只按调用者能访问的范围读取。

## 数据与交互边界

共享文件的所有参与者都可能读到文件内容。身份牌、密钥或只给一个人看的内容不能只靠页面隐藏；按产品内 `apps-together` 指南设计数据边界。

展示别人写的文字时用 `textContent` 或能转义的渲染方法。文件调用失败要显示原因，读不到不能显示成没有数据。撤权和离线也要给出可操作的说明。

这些实现建议来自产品内的 App 指南。目前没有独立的内容政策、商业条款或审核承诺。
