App 是一个文件夹：一份 `manifest.json`，加上页面、脚本和可选的 Agent 工具。它可以在任务里加工作页面，让群成员一起编辑文件，也可以给 Agent 提供工具和技能。使用者从市场选择安装。

本章写给想做 App 并上架市场的开发者。按下面的顺序读，每一步都有可检查的结果。

<Note>本章按 2026-10-30 的开发版本核对：App API 当前为 22，最低支持 3。正式版与 Beta 支持的 API 可能更低；在目标客户端上装一次，确认它接受你声明的版本。</Note>

## 源码放在哪

市场索引是公开仓库 [GUYI-AI/gugu-apps](https://github.com/GUYI-AI/gugu-apps)。每个 App 在 `apps/<id>.json` 有一份登记，记下每一版的源码仓库、提交、目录和包的校验值。客户端只安装登记过的那一份字节。

### 外部开发者：代码在自己的仓库

这是普通贡献者的路径。

1. 源码放在你自己的公开 GitHub 仓库。App 可以占整个仓库，也可以只占其中一个目录。
2. 要发布的提交合并进该仓库的默认分支。索引仓的脚本会检查这一点，只在其他分支或 fork 上的提交会被拒绝。
3. Fork 索引仓，运行一条命令生成登记，提一个 PR：

```sh
npm ci
node scripts/add-version.mjs <owner/repo> <完整40位提交> <App所在目录>
```

App 在仓库根目录时，最后一个参数写 `.`。完整步骤见[提交到 App 市场](/apps/publishing)。

市场上已有代码在其他仓库的 App。例如 `studio` 登记的是 `shuxueshuxue/promo-skills` 仓库根目录，`spexcode` 登记的是 `shuxueshuxue/Spexcode` 的 `distribution/gugu/spexcode` 目录。

### 官方 App：代码在索引仓的 sources/

咕咕团队自己的 App 放在索引仓的 `sources/<id>/`。发布一版要两个 PR：

1. **源码 PR**：修改 `sources/<id>/`，按 squash 方式合并进 `main`。
2. **登记 PR**：用合并后 `main` 上那个提交的完整 40 位 sha 运行 add-version。分支上的提交 sha 会失败，因为 squash 合并会生成新的提交。

这类 App 登记行的 `repo` 必须写 `shuxueshuxue/gugu-apps`。客户端按这串文字判断官方 App，只有它们可以标 `firstRun`。外部 App 的 `repo` 写作者自己的仓库。

想改进某个官方 App 时，向索引仓提 PR，只修改 `sources/<该 App 的 id>`，目标分支是 `main`。

## 需要准备什么

| 阶段 | 需要 |
| --- | --- |
| 做和调试 | 咕咕桌面版、一个文本编辑器 |
| 写自动测试 | Node.js；测试放在自己的仓库 |
| 提交市场 | Git、Node.js 24 或更高、GitHub 账号和一个公开仓库 |

也可以请咕咕里的 Agent 写 App。它会先读产品内的 App 指南，再制作、安装和检查。装到这台电脑上需要你确认权限。
