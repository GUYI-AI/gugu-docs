---
title: "连接应用与设备能力"
description: "让 Agent 使用已有账号，以及电脑和手机已经授权的能力。"
---

连接应用之前，先确定资料在哪、要用哪个账号，以及希望 Agent 做到哪一步。

## 先分清是哪一项没连上

| 情况 | 去哪里处理 |
|---|---|
| 模型需要厂商账号或 API 连接 | 设置 → 订阅 |
| Agent 要读日历、文档等服务 | 助理资料中的连接应用，或资源库 → 集成 |
| 某 App 未启用、没给这位 Agent 使用 | App → 已安装 |
| 系统没有允许通知或文件访问 | 设置 → 权限；电脑控制按 Computer Use 自己的设置处理 |

## 连接一个服务

在个人助理的资料里查看连接应用，也可以从资源库和相应 App 的设置进入。选择服务，按页面要求在浏览器授权或完成配置。

> 从我已连接的日历整理本周安排，标出时间冲突，先别修改任何日程。

连接状态应显示为已连接。账号失效时重新授权，再重试刚才的工作；外部服务连接改变后，已经运行的普通任务可能需要重新打开任务。App 停用或收回权限则会在下一次调用时生效。

可连接的服务以当前列表为准。不同应用可能要求浏览器授权、账号登录或 API 配置，按实际提示操作。

## 给 Agent 使用

App 安装与授权时可指定使用的 Agent。一个应用连上了，仍需确认当前执行者在允许范围内。

需要哪项能力就连接哪项。日历连接、模型订阅和电脑控制各管自己的能力，模型登录成功不会自动完成这些授权。

## 电脑上的操作

启用 Computer Use 后，在它的设置里完成系统权限要求。Agent 操作时可在任务旁边查看「电脑」页。

对外发送或提交前需要确认的，在任务里说清楚：

> 帮我起草回复并填入，停在发送前。

## 手机上的能力

Android 在获得对应系统权限后，可提供短信、录音和照片等读取能力。可用项会出现在设备能力中；只授权本次需要的部分。

设备必须保持连接。失败时先检查目标设备、应用启用状态和系统权限，再继续原任务。
