任务在选定设备上运行，使用那台机器的文件和程序。设备列表里有电脑、服务器和手机。手机发出的消息不会把服务器里的文件变成手机本地文件。

## 选择运行位置

| 工作 | 设备怎么选 |
|---|---|
| 整理电脑里的资料、修改本地代码 | 文件所在的电脑 |
| 跑服务器上的实验或脚本 | 已连接的 Linux 服务器 |
| 用手机查看进展、补充要求 | 手机负责查看，原设备继续执行 |
| 读手机里的日程、短信、照片 | 这台手机，见[手机端](/mobile) |
| 个人助理持续接待和跟进 | 开通时选择自己的电脑或按权益使用云端 |

同一账号登录桌面版后，这台电脑会出现在「设置 → 设备」中。新建任务时选设备，或从项目卡里选择对应设备上的文件夹。

## 添加另一台机器

打开「设置 → 设备」，点「添加一台机器」，再选添加方式：

| 方式 | 做法 | 能跑的任务 |
|---|---|---|
| 「远程 SSH」 | 填 `用户@主机`、ssh 命令或 SSH 配置里的主机名，咕咕经 SSH 安装 | 「通用」和「编程」 |
| 「远程隧道」 | 在那台机器上运行页面给出的一行命令，经咕咕云连接 | 只有「通用」 |

两种方式都只支持 Linux 和 macOS，x64 或 arm64。远程隧道的命令跑完后，打开它输出的链接，点「允许」。短码 15 分钟内有效。

能自己登录服务器时，也可以在服务器终端运行官方安装器：

```sh
curl -fsSL https://download.gugu.nextmind.space/releases/server/install.sh | sh
```

这条命令装正式版。Beta 用户复制添加页面里显示的命令，它已带上版本通道。安装后按提示登录，用链接和短码确认设备，再回设备列表查看。

<Note>远程隧道和跨设备项目用法对应当前 Beta。登录确认页会显示要连接的设备，只在你自己刚执行过登录时点允许。</Note>

选择器提示某台机器这里仅支持「通用」时，要用「编程」就在这台电脑上为它补一条远程 SSH 连接。

### 机器数量上限

咕咕 server 的数量有上限。超出时页面显示「咕咕 server 已达上限」，这台机器不会被添加。可以升级会员，或先移除一台机器。

远程隧道另有上限。「远程 SSH 不占名额」，名额满了可以改用远程 SSH。

## 这台电脑能做的事

「设置 → 设备 → 这台电脑能做的事」管理本机任务的工具权限。只有这台电脑上的任务 Agent 能使用已授权的能力。

- 每类能力单独授权，例如「日历」「邮件」「终端与自动化」「快捷指令」「电脑控制」。点进一项连接，按提示在系统设置里授权。
- 「终端与自动化」和「快捷指令」每次运行前都会先问你。
- 打开「全部拒绝」开关会暂停所有本机工具，原有授权保留。关掉开关即恢复。
- 「最近调用」列出每次调用的结果，包括被拒绝或系统没给权限的情况。

日历、邮件、终端与自动化、快捷指令等目前只在 Mac 上提供。Windows 和 Linux 上可用的项目较少，以页面列出的为准。

Agent 操作电脑时，目标窗口顶边会出现一个标签，写明谁在操作。点「停止」后它不会再动这台电脑。

## 手机也能运行任务

Android 手机启用任务后，会以「手机」类型出现在设备列表。手机上的日历、短信、照片等权限只给这台手机上的任务 Agent 使用。启用方法见[手机端](/mobile#让手机自己运行任务)。

## 保持工作可用

设备在线只说明连接正常。执行还需要 Agent 可用、账号或模型额度有效，以及所需应用已经授权。

电脑关机、断网或服务停止时，界面会显示离线或连接错误。在原设备恢复服务后，再回原任务继续，先确认上一轮有没有执行到一半。

## 文件不会自动同步

项目可以挂不同设备的文件夹，文件内容仍分别保存在各台机器上。跨设备交付用附件、群文件夹或大家都能访问的仓库。

普通任务运行在所选设备；个人助理的运行位置按[个人助理](/assistant)中的开通与搬家流程管理。

## server 与日常管理

咕咕 server 是远程 Linux 上的无界面运行端，任务使用那台机器的目录和已安装引擎。管理连接、改名或移除机器从「设置 → 设备」进入。关闭桌面窗口不会停止服务器上的进程。远程执行是否继续，取决于那台机器的服务和 Agent 是否仍在运行。

server 版本太旧时，桌面会自动给它更新。那台机器上有 agent 在运行时，会等空闲再更新；也可以点「现在重启更新」，确认「重启」后正在运行的这一轮会被中断。版本旧到无法自动更新时，页面会给出安装命令，在那台机器上重新运行即可。

手机查看、回复、审批和附件预览见[手机端](/mobile)。查看本机 CPU 和内存见[资源监视器](/resource-monitor)。
