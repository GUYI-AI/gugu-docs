---
title: "把文献整理成组会提纲"
description: "从几份已有资料开始，先核对证据，再写提纲，最后交付到协作群。"
---

准备两三篇可供 Agent 读取的文献或笔记，放在同一个文件夹。最后得到一张资料表和一份组会提纲。

材料含 PDF 等格式时，先确认当前 Agent 或 App 能读取；读取失败要换可读格式或按提示补齐能力。结果中的出处必须回原文核对。

## 1. 从材料所在的文件夹开始

在「项目」的「+」中选择「使用现有文件夹」，选中材料目录。打开项目，点这个文件夹，选择 Agent、模型和实际运行设备。

已有对应项目时，把资料文件夹挂进去即可。同一课题的不同目录可以放在同一个项目里。

## 2. 先做资料表

```text
先列出这个文件夹里能读取的文献，只处理前面三篇。
把每篇的研究问题、方法、主要结论、局限整理为 literature-table.md。
每项附原文页码或章节位置。缺的信息写“未提供”，读不到的文件单独列出来。
这一步先交资料表，等我确认后再写组会提纲。
```

打开表格，抽查每篇的一处结论和一处出处。数字与原文不一致时，在原会话指出具体行，让 Agent 重新核对。

## 3. 确认后写提纲

> 按刚确认的资料表，写一份组会提纲到 meeting-outline.md。顺序是研究问题、各篇证据、共同点和分歧、我们可以讨论的问题。每项保留来源；把我的想法和论文结论分开写。

从回复打开提纲，和聊天并排。可以直接要求「第二部分再短一点」或「把仍缺证据的结论标出来」。

需要试两种讲述顺序时，用会话分叉分别继续；需要保留的文件另取名字，避免两条会话修改同一个文件。

## 4. 交付给一起做事的人

把需要接手的人或已有 Agent 加入项目群。让当前 Agent 把最终资料表和提纲发到群文件夹，再从实际成员里点名，说明谁检查哪部分。下面的名字是分工示例。

> 把两份成品放进群文件夹。@写作助手 请只检查提纲的论证顺序，把意见回复在提纲这条消息下面。

检查点：资料能打开、原文出处对得上、未知项仍明确、接手者知道要检查什么。任务完成后再归档；归档会停止仍在运行的 Agent。

需要讨论某张图时，从那条消息[开话题](/chat#话题)。跨设备材料如何组织，见[项目与文件夹](/projects)。
