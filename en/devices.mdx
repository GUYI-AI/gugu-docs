A task runs on the selected device and uses that machine's files and programs. The device list holds computers, servers, and phones. Sending a message from your phone does not turn files on a server into files on your phone.

## Choose where to run

| Work | Which device |
|---|---|
| Organize files on your computer, edit local code | The computer where the files are |
| Run experiments or scripts on a server | A connected Linux server |
| Check progress or add requests from your phone | The phone is for viewing; the original device keeps running the work |
| Read calendar, SMS, or photos on your phone | This phone, see [Mobile](/en/mobile) |
| A personal assistant for ongoing questions and follow-up | Your own computer chosen during setup, or the cloud if your plan includes it |

After you sign in to the desktop app with the same account, this computer appears in **Settings → Devices**. Choose a device when creating a new task, or pick a folder on that device from a project card.

## Add another machine

Open **Settings → Devices**, click **Add a machine**, and pick a method:

| Method | How | Tasks it can run |
|---|---|---|
| **Remote SSH** | Enter `user@host`, an ssh command, or a host name from your SSH config; gugu installs over SSH | **Work** and **Code** |
| **Remote tunnel** | Run the one-line command shown on the page on that machine; it connects via Gugu Cloud | **Work** only |

Both methods support Linux and macOS only, on x64 or arm64. After the tunnel command finishes, open the link it prints and click **Allow**. The short code is valid for 15 minutes.

If you can sign in to the server yourself, you can also run the official installer in its terminal:

```sh
curl -fsSL https://download.gugu.nextmind.space/releases/server/install.sh | sh
```

This command installs the stable release. Beta users should copy the command shown on the add page, which already carries the release channel. After installing, sign in as prompted, confirm the device with the link and short code, then check the device list.

<Note>Remote tunnel and cross-device projects follow the current Beta. The sign-in confirmation page shows the device being connected. Only allow it if you just ran the sign-in yourself.</Note>

If the picker says a machine supports **Work** only, add a Remote SSH connection to it from this computer to use **Code**.

### Machine limits

The number of gugu servers is limited. Past the limit, the page shows "Gugu server limit reached" and the machine is not added. Upgrade your membership or remove a machine first.

Remote tunnels have their own limit. "Remote SSH doesn't count", so you can switch to Remote SSH when tunnel slots are full.

## What this computer can do

**Settings → Devices → What this computer can do** manages tool permissions for tasks on this computer. Only task Agents on this computer can use the tools you authorize.

- Each category is authorized on its own, for example **Calendar**, **Mail**, **Terminal & automation**, **Shortcuts**, and **Computer control**. Open one, connect it, and grant the system permission when prompted.
- **Terminal & automation** and **Shortcuts** ask you before every run.
- Turning on the **Deny all** switch pauses all local tools and keeps existing permissions. Turn the switch off to resume.
- **Recent calls** lists the result of each call, including calls that were refused or lacked system permission.

Calendar, Mail, Terminal & automation, Shortcuts, and similar categories are Mac-only for now. Windows and Linux offer fewer categories; the page shows what is available.

While an Agent operates the computer, a tag on the top edge of the target window names who is in control. Click **Stop** and it no longer touches this computer.

## Phones can run tasks too

Once you enable tasks on an Android phone, it appears in the device list as **Phone**. The phone's calendar, SMS, photo, and other permissions are only for task Agents on that phone. See [Mobile](/en/mobile#let-the-phone-run-tasks) to set it up.

## Keep work running

A device being online only means the connection works. Running work also needs an available Agent, a valid account or model quota, and the required apps authorized.

When a computer is off, offline, or its service stops, the interface shows it as offline or shows a connection error. After the original device's service is back, return to the original task. First check whether the previous turn stopped halfway.

## Files are not synced automatically

A project can attach folders from different devices, but file contents stay on each machine. To deliver across devices, use attachments, a group folder, or a repository everyone can reach.

Regular tasks run on the selected device. Where the personal assistant runs is managed through setup and moving in [Personal assistant](/en/assistant).

## Gugu server and everyday management

Gugu server is the headless runtime on a remote Linux machine. Tasks use that machine's directories and installed engines. Manage connections, rename, or remove machines from **Settings → Devices**. Closing the desktop window does not stop processes on the server. Whether remote work continues depends on whether the service and Agent on that machine are still running.

When a server's version is too old, the desktop updates it automatically. If agents are running there, it waits until they are idle. You can also click **Restart and update now**; after you confirm **Restart**, the turn currently running is interrupted. If the version is too old to update automatically, the page shows the install command to run again on that machine.

For viewing, replying, approving, and attachment previews on the phone, see [Mobile](/en/mobile). To check CPU and memory on this computer, see [Resource monitor](/en/resource-monitor).
