When creating a task, make three choices.

| Choice | What it decides |
| --- | --- |
| Engine | Which execution tool to use, such as Codex, Claude Code or OpenCode |
| Model | Which model to use, and whether it is billed to your own vendor account or to gugu credits |
| Device and folder | Where files are read and programs run |

An Agent does the work you assign. It can also have its own contact identity and take part in group chats. The engine decides how work is executed, and the model provides the reasoning. One engine can use different models.

## Install and choose an engine

Check what is installed in **Library**. When creating a task, the picker also separates installed engines from ones that need installing; follow the prompts to install.

Current options include Codex, Claude Code, Qwen Code, GitHub Copilot, OpenCode, Hermes Agent, MiMo Code, CodeBuddy Code, Pi and more. They differ in display modes, sign-in methods and model connections. Check **Library** and the picker for the options available in your version.

Start with one engine that already works and finish a small task. Compare other options later as your work requires. You do not need to install every engine at once.

## Your own subscriptions and models provided by gugu

Manage existing vendor subscriptions or API connections in **Settings → Subscriptions**. When choosing a model, your own vendor models and models provided by gugu, billed in credits, are shown separately.

Models provided by gugu are connected by gugu, so you do not configure a gateway address yourself. Check the picker for compatibility with the current engine and mode. Some engines may still require your own account as a prerequisite.

Models and plans on sale change, so the docs do not keep a full list of models and prices. For choosing and billing details, see [Models, subscriptions and credits](/en/models).

## Create an Agent

Each of these opens the same new-Agent page:

- **New Agent** at the top of the **Chats** list.
- The **Create Agent** button beside a device section in **Contacts**. When you have no Agents yet, the empty list shows the same button.
- **File → New agent** in the menu bar at the top of the Windows window.
- In a group, open **Group members** and choose **New Agent in this group**. The new Agent joins this group as soon as it is created.

Write the first request, choose the engine, model and device, then send. The Agent starts working. For what comes next, see [Task workspace](/en/tasks).

## Adjust an Agent

Select one of your Agents in **Contacts** and open its settings. The tabs on the left are:

| Tab | What it is for |
|---|---|
| **Profile** | Name, avatar, bio, and **Pause Agent** |
| **Look** | Only the personal assistant has this tab |
| **Share** | **Forward to contact** or **External sharing**. See [Contacts and sharing](/en/contacts) |
| **Scheduled tasks** | Have it do work on a schedule. See [Schedules](/en/schedules) |
| **AI model** | Change the model. The page explains when the change takes effect |

With **Pause Agent** turned on, it only responds to your direct messages. Turn the switch off to resume.

## Continue with the same Agent

A task keeps the requests, process and replies. Go back to the original task to add requests; you do not need to re-explain the whole background.

An Agent in a task can also join the project group as a contact. To have it continue something, mention it or reply to its message, and say what result you want.

An online status means the device it runs on is connected. Work status comes from the execution process. Handle connection failures, expired sign-ins and insufficient quota as the interface prompts. A successful tool run only means that step finished; still check the final deliverable.

To open past work, see [Task workspace](/en/tasks). To check progress on your phone, see [Mobile](/en/mobile).
