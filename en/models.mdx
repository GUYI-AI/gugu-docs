## Choose a model in the input box

The model dropdown groups models by source:

| Source | How it is billed |
|---|---|
| **Your provider models** | Uses the subscription or API connection already on the selected device, billed by that service |
| **Models provided by Gugu · billed in credits** | Uses credits from your gugu account |

If a model is unavailable, check its entitlements and management options in **Settings → Models**. The model menu shows only the items you can currently choose.

**Reasoning effort** sets how hard the model thinks. It appears when the Agent and model support it. Higher levels may take longer and use more credits or provider quota. For simple tasks, start with the default.

## Agents and models are separate

The Agent decides how a task runs. The model decides which provider and quota the request uses. Changing the model does not move the task to another device, and it does not change the Agent's identity in a group.

When a sign-in is required, first check which source you are using. Some Agents can use gugu models without a provider subscription. A few Agents still require their own account. Follow the explicit prompts in the picker.

## Manage existing subscriptions

**Settings → Subscriptions** shows your gugu membership and the Agent connections on the selected device. "Credentials stay on the selected device", so on another machine, check that machine's actual setup.

Claude Code and Codex can keep several connections. Click **Add connection** and choose **Account sign-in** or **API Key** as the connection method. With an API key, you can tick **Use a third-party API** and fill in the **API address**. An account already signed in through the command line shows as **Existing CLI configuration**. A key without an API address shows as **Official API**.

All sessions use the current connection. Switching closes running sessions; their next message continues on the new connection. If sessions are still working, the page says how many, and switches only after you confirm **Close and switch**.

<Note>From Beta. In the stable release, follow what the page in your installed version says.</Note>

Switching the subscription connection and picking a model in the current task are two separate actions. The first decides which account this Agent uses on this device. The second decides which model this request uses.

Quota readings show when they were read. When the provider does not supply a reading, or it cannot be read right now, the page explains why. "Could not read" does not mean the quota is zero.

## gugu credits

**Settings → Usage** shows how much you have used and which tasks used it. The **Subscriptions** page shows membership entitlements, this period's allowance, and non-expiring credits.

- This period's allowance refreshes at the end of the cycle. Unused allowance does not carry over.
- Credits from top-up packs and the sign-up bonus do not expire.
- This period's allowance is used first, then non-expiring credits.
- Your membership tier decides which models are available. For purchased credits, follow the terms on the purchase page.

Manage membership, renew, buy top-up packs, redeem gift codes, and view purchase history in the [membership dashboard](https://gugu.nextmind.space/dashboard/). For current prices, see the [pricing page](https://gugu.nextmind.space/en/pricing.html). The price shown at checkout applies.

## Common choices

If you already have a provider subscription, pick your own model first. To use gugu quota directly, pick the group marked "billed in credits". Check the source before switching. If you hit a quota or permission error, follow the prompt.

Community points in the Forum are not used for model billing and cannot buy or be exchanged for quota. See [Forum and point bounties](/en/forum).
