`manifest.json` sits at the root of the App folder. Validation is strict: a misspelled or unknown field makes installation fail. A valid manifest only means the App can be installed; the person still has to agree to the permissions it declares.

## Identity and compatibility

| Field | Required | Rule |
| --- | --- | --- |
| `id` | Yes | Matches `^[a-z0-9][a-z0-9-]{1,63}$`: 2 to 64 lowercase letters, digits or hyphens, starting with a letter or digit, no dots |
| `name` | Yes | 1 to 64 characters |
| `version` | Yes | `x.y.z`, digits only; a published version number is never reused |
| `apiVersion` | Yes | Integer from 3 to 22. Above what the client supports, it says gugu needs updating; below 3, it says to rewrite for the current API |
| `platforms` | To install and publish | `["desktop"]`, `["phone"]` or both; not empty, no duplicates; needs `apiVersion` 12 or higher |
| `engines.gugu` | To publish | Only `>=x.y.z` or `^x.y.z`: the oldest gugu version |
| `description` | No | 1 to 280 characters; its first sentence appears in the App list Agents read |
| `subtitle` | No | 1 to 30 characters, the line under the name in the market; needs API 8 |
| `examples` | No | 1 to 3 things a person might say to an Agent, up to 80 characters each; clicking one on the market page starts a task with it |
| `author` | No | 1 to 64 characters; shown, not verified |
| `icon` | No | Path to a raster image in the bundle, no SVG; the market requires PNG, at most 32 KiB and 512px per side |
| `homepage` / `repository` | No | `https://` links, up to 200 characters |
| `license` | No | SPDX identifier or a short license name, up to 64 characters; not verified |
| `categories` | No | 1 to 4 distinct category slugs matching `^[a-z0-9][a-z0-9-]{0,31}$` |
| `localized` | No | Per language tag (`en`, `zh-CN`): `name`, `description`, `subtitle`, `examples`, same limits |

The market has three sections: `research` (Research), `productivity` (Productivity) and `developer` (Developer). Other slugs go under **Other**.

The market check joins `- name (id): first sentence of description` into one line. That line may be at most 120 characters, or the version is refused. Write the first sentence for Agents, saying what the App does. Put the full description for people in the README.

### Platforms

`platforms` describes where the human-facing interface works. It says nothing about where Agent programs run.

- Phones do not run Agent features. An App declaring `phone` may still request `agents:*` capabilities; those features work only on computers.
- Phones do not support `notifications`. Declaring both `phone` and `notifications` is refused at publication and installation.
- Package installs on the phone refuse gugu's settings page (`hostPage`). Tool Apps run and are configured on gugu desktop.
- Whether the App really fits a phone screen is the author's responsibility. Installed older Apps keep running without this field.

## Pages, background and Agent features

| Field | Rule |
| --- | --- |
| `entry` | Bundle-relative HTML path |
| `background.entry` | Optional background page; one per App, started when the App is enabled, running even when no page is open |
| `contributes.tabs` | 1 to 8 pages |
| `contributes.mcpServers` | 1 to 4 programs, in the forms below |
| `contributes.skills` | Bundle folder with one `<name>/SKILL.md` per skill |
| `contributes.agentInstructions` | 1 to 8000 characters of standing instructions for Agents; needs at least one program and `agents:tools` |
| `contributes.toolsListed` | Only `true`; at first install, suggests listing the tools directly to Agents (the person can switch back); needs a program |
| `settings` | 1 to 32 fields drawn by gugu as a settings page; needs API 5 |

Every path must stay inside the bundle: no leading `/`, no backslashes, no `.` or `..` segments, at most 256 characters.

Each `mcpServers` entry takes one of three forms:

| Form | Example | Notes |
| --- | --- | --- |
| JavaScript tools module | `{ "tools": "tools.js" }` | Each export is one tool; at most one per App |
| Local program | `{ "name": "rows", "command": "node", "args": ["server.mjs"] }` | `command` is `node`, a bundle `./path` or a program name on PATH; up to 32 `args`; optional `env` |
| Capability provided by gugu | `{ "name": "browser-use", "host": "browser-use" }` | `host` is `browser-use` or `computer-use`; needs API 5; desktop only |

A program `name` matches `^[a-z][a-z0-9-]{0,31}$` and is unique within the App.

An App without HTML pages must provide programs or skills. From API 5, tool Apps may omit `entry` and `tabs`; opening them shows gugu's settings and status page.

Each `settings` field has a `key` (matching `^[a-z][a-zA-Z0-9_]{0,63}$`, unique), a `title` (up to 80 characters), a `type`, and optional `description` and `default`. `type` is `string`, `boolean` or `select`. A `select` has 1 to 32 `options`, and its `default` must be one of them. Programs read the JSON from the `GUGU_APP_SETTINGS` environment variable.

### Each page

| Field | Rule |
| --- | --- |
| `name` | Matches `^[a-z0-9][a-z0-9-]{0,31}$`, unique within the App |
| `title` | 1 to 48 characters |
| `entry` | Optional; defaults to the top-level `entry` |
| `icon` | Optional raster image in the bundle |
| `opensFiles` | Optional `{ "session": [...], "chat": [...] }`, at least one side, 1 to 16 claims each; a suffix such as `.csv`, or a file name such as `TODO.md` or `todo-*.md` |
| `fileIcons` | Optional; each key must be one of this page's `opensFiles` claims |
| `chatFile` | Optional top-level file name shown when the App opens in a chat; must match this page's `opensFiles.chat`; at most one page per App; needs API 14 |
| `sideWidth` | Optional integer from 280 to 960: the page's width in pixels beside a chat or a task's conversation; needs API 16 |
| `menu` / `toolbar` | Optional, up to 8 / 6 entries of `{ "id", "title" }`, `title` up to 32 characters; a click fires `onCommand` |
| `perSession` | Optional, only `true`: one page per task; cannot combine with `opensFiles` or the settings page |
| `hostPage` | Optional, only `"settings"`: use gugu's settings page; then no `entry`, `opensFiles` or page commands |

`opensFiles` offers an App as a way to open a file. The person's own choice wins. When several Apps claim the same file, the person picks.

## Permissions

`permissions.capabilities` holds up to 12 entries and `permissions.network` up to 16 hostnames.

| Capability | Allows |
| --- | --- |
| `files:read` | Reading files of the person's chats and of this computer's tasks |
| `files:read:all-machines` | The same, plus read-only access to tasks' files on other computers |
| `files:write` | Creating, changing and deleting files; does not include reading, so declare `files:read` too if you read |
| `chat:relay` | Private messages to chat members in the person's name, marked as from the App |
| `chat:read` | The person's chats, members and messages; needs API 6 |
| `agents:read` / `:all` / `:all-machines` | See Agents this App started / all on this computer / plus other computers |
| `agents:history` / `:all` | Read conversations of Agents this App started / of all on this computer |
| `agents:control` / `:all` / `:all-machines` | Start, contact or stop Agents in that scope; spends the person's quota |
| `agents:tools` | Give the App's programs, skills and standing instructions to Agents on this computer |
| `notifications` | System notifications; not on phones |

Declare only one level per family. For example, do not declare both `agents:read` and `agents:read:all`.

Declaring programs, skills or `agentInstructions` requires `agents:tools`. Declaring `agents:tools` without any of the three is also refused.

`network` lists bare hostnames such as `api.example.com` or `*.example.com`, with at least two labels and no scheme, port or path. IP addresses, `localhost`, `.local` and `.internal` are refused. Pages reach these hosts over HTTPS and WSS only.

`firstRun`, `featured` and `unlisted` are fields of the [market registry](/en/apps/publishing). They cannot go in the manifest.

## API versions

Set `apiVersion` to what the newest API you use needs. The market uses this number to hand each client the newest version it can install. Betas with the same version number may support different APIs, so `engines.gugu` cannot replace it.

| API | Added or changed |
| --- | --- |
| 3 | Oldest version still supported |
| 4 | `refs` to name files; the old `about` parameter removed |
| 5 | Tool Apps may omit HTML; gugu's settings page, `settings`; `host` programs |
| 6 | `chat:read`, `gugu.chats`, `gugu.messages` |
| 7 | Working-copy file links with a place in a task's chat reach `onLink` |
| 8 | `subtitle` |
| 9 | `gugu.forum` |
| 10 | Sending without naming a place, the person picks (handled by `dispatch` from 15) |
| 11 | `gugu.modal` dialogs |
| 12 | `platforms` |
| 13 | `linkTo`, `openLink` |
| 14 | A page's `chatFile` |
| 15 | `gugu.dispatch`; `compose`, `send`, `messageAgent`, `spawnAgent` removed |
| 16 | A page's `sideWidth` |
| 17 | Running programs on a chosen computer; `gugu.sessions` for external session history; `dispatch`'s `spawn.device` |
| 18 | App data file markers (`appData`), file `metadata`, chat folder view preference, `showContextMenu` |
| 19 | `files.keep` and the `keep` field of file entries |
| 20 | `files.download` and `files.keep` accept several files |
| 21 | A tools module's `run` receives an abort `signal` |
| 22 | `gugu.projection`: local picture and input resources |
