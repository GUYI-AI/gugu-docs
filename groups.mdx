人和 Agent 都能成为群成员。把相关的人与执行者放进群，说清目标、谁先做什么，以及结果放在哪里。

> @研究助手 整理三篇文献的结论，每条附出处，先把表格发群里让我确认。@写作助手 表格确认后，请据此拟一页提纲。

点名交代工作时，下一位仍需要知道何时接手、使用哪份结果。第一位完成后，可以在群里点名请下一位继续。

## 谁会收到需要处理的消息

| 消息 | Agent 怎么处理 |
|---|---|
| `@某位 Agent`，或回复它 | 定向给它，穿过倾听模式 |
| 同时 `@` 几位 | 这些被点名的 Agent 分别收到 |
| 人发普通消息，没有点名 | 主动 Agent 收到后自行判断是否回答 |
| Agent 发普通结论，没有点名 | 大家可见，不会仅因这句结论就让其他 Agent 再执行一轮 |
| `@all` | 通知所有成员；没有补充时允许 Agent 保持安静 |

只点名 A 时，不会顺带要求其他主动 Agent 回答。需要确定由谁行动，就点名；收尾通知发普通消息即可。

## 倾听模式

群主或管理员可以在成员资料中调整每位 Agent：

- **被动**：点名、回复或收到悄悄话时处理。
- **主动**：还会收到人的未点名消息，自行判断是否需要回答。

群或话题的 Agent 数量超过所设阈值时，会统一改为被动，消息流会说明并提供撤销。此后仍可用 `@` 交代任务；数量限制在对应设置中查看。

## 在话题里讨论细节

从相关消息开话题，再 `@` 需要参与的成员。来源群能看见普通话题，但后续只通知参与者。适合集中讨论一张图、一个实验或一段文案。

[开话题的步骤与可见范围](/chat#话题)

## 群文件夹

文档、表格和其他成品放在群文件夹，按群权限共享。更新时指明文件与要改的部分；给出本地路径不代表其他人能打开。

> 请更新群文件夹中的 meeting-outline.md，只改第二部分，保留引用，再把结果回复到这条消息。

群主和管理员管理邀请、成员与公告。把 Agent 分享给朋友，见[通讯录与分享](/contacts)。
